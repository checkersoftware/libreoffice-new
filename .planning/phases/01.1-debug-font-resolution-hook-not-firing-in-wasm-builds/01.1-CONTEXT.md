# Phase 01.1: Debug Font Resolution Hook Not Firing in WASM Builds - Context

**Gathered:** 2026-02-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the WASM font resolution hook so it actually fires at runtime. The hook was implemented in Phase 1 but is not working — the JS callback never triggers, fonts render with fallbacks, and the WASM runtime aborts with an uncaught exception.

</domain>

<decisions>
## Implementation Decisions

### Build Environment
- The WASM build IS configured with `--enable-emscripten-jspi` (JSPI is enabled)
- `HAVE_EMSCRIPTEN_JSPI=1` in the production/test build
- `EM_ASYNC_JS` is the CORRECT path for this build — the sync fallback is secondary
- The Electron app builds LibreOffice into WASM with a specific flag set (see full flags below)

### Target Host
- Electron app only — no browser-only deployment
- The Electron app defines `Module.resolveSystemFont` which should be called by EM_ASYNC_JS
- Host callback currently logs "HALLO ${familyName}" but is never reached

### Observed Symptoms
- Fonts render with fallback/wrong fonts (not the requested ones)
- `Module.resolveSystemFont` JS callback is never called (no "HALLO" output)
- WASM runtime throws uncaught exception / "Aborted" error
- User has not yet tested with the latest debug fprintf statements (commits f1c7a05, 9a04612)

### JSPI Strategy
- JSPI path (EM_ASYNC_JS + Module.resolveSystemFont) is the primary path
- Sync fallback (EM_JS + Module.resolveSystemFontSync) is nice-to-have for dev/testing
- Keep both paths via #if HAVE_EMSCRIPTEN_JSPI conditional
